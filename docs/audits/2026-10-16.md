# Аудит проекта — 16 октября 2026

Выполнены анализ исходников, исправления интерфейса и HTTP-границы, улучшения CI,
организация документации и автоматизация проверок. Это аудит рабочего дерева:
до начала работы в нём уже были изменения безопасности, AI и пользовательских
сценариев. Они сохранены; таблица ниже описывает доработки этого прохода.

Проект собирается, проверки кода и тесты проходят. Готовность production-установки
не подтверждена: нет доступа к Docker daemon и работающей тестовой PostgreSQL.
Проверки интерфейса используют фикстуры API и не подменяют интеграционный прогон.

## Scope and Coverage

Режим: **full**. Стек: Vue 3, Pinia, Vue Router, CSS-токены, Vite/PWA;
Express 5, TypeScript, Prisma/PostgreSQL; Docker Compose, GitHub Actions.
Из проектных соглашений изучены `CONTRIBUTING.md`, `SECURITY.md`, корневые README,
конфигурация ESLint/Prettier. `AGENTS.md` в репозитории не найден.

Проверены 20 маршрутов: вход, регистрация, главная, дневник, чат, анализ рисунка,
список и страница курса, домашнее задание, аналитика, профиль, прогресс, галерея,
челленджи, дыхание, музыка, библиотека, администрирование, кабинет терапевта,
организация. Браузерная матрица: 320, 768, 1440 CSS px × светлая/тёмная тема =
120 сочетаний маршрут/размер/тема. Дополнительно: ошибки API, сохранность текста
при неудачной отправке дневника, вложенные окна, Escape, возврат фокуса,
редактор нового курса и reduced motion.

Базовые страницы преимущественно проверены с пустыми наборами данных;
для страницы курса и задания есть содержательные фикстуры. Загрузка проверялась

прогона всех задержанных ответов. Длинные реальные истории, заполненные кабинеты
всех ролей, настоящие screen reader, Safari/Firefox и физический мобильный браузер

прогон масштаба 200% не выполнялся. Это не сертификация WCAG.

## Безопасность и DevSecOps

| Область               | Подтверждённая проблема                                                                              | Исправление                                                                                                                                                 |
| --------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Запросы браузера      | CORS ограничивал чтение ответа, отдельной проверки Origin для мутаций не было                        | `backend/src/middleware/requestOrigin.ts`: точное сравнение Origin для небезопасных методов; отклонение opaque и cross-site запросов. Есть негативные тесты |
| Ошибки HTTP           | JSON parser мог отдавать 500 для некорректного JSON; его ошибка содержит фрагмент тела               | Сохранён статус 400; тело parser-ошибки не возвращается и не записывается в лог                                                                             |
| Корреляция журналов   | Принимался неограниченный пользовательский request id                                                | Разрешён безопасный набор символов длиной до 128; иначе сервер генерирует UUID                                                                              |
| Приватное кеширование | Rate-limit ответы появлялись до `no-store`                                                           | `no-store` устанавливается до общего limiter                                                                                                                |
| nginx                 | Локальный `add_header Cache-Control` отменял наследование защитных заголовков                        | Общий `security-headers.conf` явно подключён в соответствующих location                                                                                     |
| nginx                 | Regex статических расширений мог перехватывать API URL; immutable применялся к нехешированным файлам | `/api/` имеет `^~`; immutable только для `/assets/`; HTML, manifest и worker перепроверяются                                                                |
| Аудит зависимостей    | Неполный JSON/error от registry мог выглядеть как отсутствие уязвимостей                             | Fail-closed при неполном отчёте, timeout, проверка порогов и обоснований исключений                                                                         |
| Supply chain          | По умолчанию высокие уязвимости build tooling не блокировали gate                                    | High/critical блокируют для всего дерева; исключения остаются явными                                                                                        |
| CI/CD                 | Workflow публикации мог начать сборку без зависимости от полного CI                                  | Переиспользуемый CI, `needs: verify`, минимальные permissions, timeout и concurrency                                                                        |
| Происхождение образов | Публикация отключала provenance                                                                      | Включены provenance и SBOM; фактический выпуск требует проверки в GitHub                                                                                    |
| Секреты и данные      | `.env.production` и локальные рисунки не были явно закрыты всеми правилами ignore                    | Git и Docker build context исключают `.env.*`, кроме примера, локальные рисунки и артефакты браузерных проверок                                             |
| Контроль кода         | Общий `no-console: off` переопределял запрет console в backend                                       | Запрет backend снова действует и проходит lint                                                                                                              |

Проверка Origin дополняет SameSite-cookie. Для запросов без Origin сохранена
совместимость с небраузерными клиентами; cross-site Fetch Metadata всё равно
отклоняется. Это не реализация отдельного CSRF-токена. `FRONTEND_URL` должен точно
совпадать с origin интерфейса, включая протокол и нестандартный порт.

Решения по Origin сверены с [OWASP CSRF Prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html).
Поведение наследования заголовков — с [официальной документацией nginx](https://nginx.org/en/docs/http/ngx_http_headers_module.html).

## Функциональность и организация

PDF-экспорт назывался дневником, но выводил прогресс и анализы рисунков без самих
записей. Теперь он включает содержание дневника и даты на русском. Отдельный тест
проверяет выборку владельца и передачу записи в PDF. Формулировка «Книга исцеления»
заменена на «Личный дневник».

Материалы партнёрств перенесены в `docs/outreach`, добавлены карта архитектуры,
инструкция эксплуатации и индекс документации. Изображения сгруппированы в
`frontend/src/assets/images`, импорты обновлены. Удалены пустые каталоги.
Код уже имел разумные слои controllers/services/middleware и views/components/
composables/stores; они сохранены. Единый lock-файл остаётся в корне.

Добавлены общие команды `build`, `test`, `type-check`, `check`, `test:browser`.
Указано минимальное окружение Node.js 22.12+. Это соответствует инструментам
сборки; фактические локальные проверки выполнены на Node.js 26.8.1.

## Повторный проход: надёжность пользовательских сценариев

После очистки проекта устранены дополнительные ошибки, воспроизводимые при
задержанных ответах и сетевых сбоях:

| Сценарий                                                                         | Исправление                                                                                                       | Проверка                                          |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Ответ `/profile` приходит после выхода или смены аккаунта                        | Версия клиентской сессии блокирует устаревший ответ; старый запрос не сбрасывает блокировку нового                | Unit-тесты с управляемым порядком ответов         |
| Завершение сеанса не дошло до сервера                                            | Пользователь видит ошибку и может повторить выход; интерфейс не утверждает, что cookie удалена                    | Unit и браузерный тест повторного выхода          |
| Старый запрос возвращает 401 после нового входа                                  | Каждый Axios-запрос помечается локальной версией сессии; устаревший 401 не завершает новую сессию                 | Браузерный тест с задержанным ответом уведомлений |
| Несколько обращений требуют восстановления сессии                                | Запрос `/profile` объединяется; переход на вход не дублирует уведомление                                          | Unit и браузерные сценарии                        |
| Сохранение дневника, курса, задания или профиля завершается после смены аккаунта | Версия состояния профиля блокирует запись в состояние нового аккаунта                                             | Unit-тесты всех шести типов мутаций               |
| Редактируется запись за прошлую дату                                             | Сохраняются дата и результат анализа из ответа сервера; исходная запись не переносится на сегодня                 | Unit-тест календарной даты и анализа              |
| Первая активность после входа                                                    | Клиент сохраняет серию, полученную от сервера; дни считаются как календарные, без ошибки перехода на зимнее время | Unit-тесты, отдельно `TZ=Europe/Berlin`           |
| БД временно недоступна при проверке токена                                       | Backend возвращает 503 вместо 401; проверка роли использует уже полученную строку пользователя                    | API-тесты с отказом БД и устаревшей ролью в JWT   |

Начальный экран монтируется после завершения проверки маршрута: это предотвращает
кратковременный показ оболочки без сессии и пропуск первой загрузки уведомлений.

JWT дополнительно ограничен используемым алгоритмом HS256 и проверкой обязательных
полей. Отказ сети при обновлении профиля больше не стирает ранее загруженное
состояние. Неверный пароль на форме входа не вызывает уведомление об истечении сессии.

Следующий этап по влиянию: сначала подтвердить интеграционные сценарии с реальной БД
и восстановление резервных копий; затем перевести большие экспорты на пакетную
обработку и добавить проверки заполненных экранов. После измерения нагрузки решать
вопросы общего rate limiter и масштабирования. Новый визуальный редизайн сейчас
имеет меньший приоритет, чем сохранность данных и проверяемость эксплуатации.

## Verification

Проверено локально:

- `npm run check`: ESLint, Prettier, оба type-check, тесты, обе production-сборки, audit.
- Тесты после повторного прохода: 42 backend + 22 frontend + 4 проверки audit gate.

  14 сценариев, включая матрицу 20 маршрутов × 3 ширины × 2 темы и проверки сессий.
- `npm audit --json`: 0 уязвимостей по ответу registry в момент проверки;
  allowlist пуст. Это не аудит ОС внутри контейнеров.
- `docker compose config --quiet` и вариант `-f docker-compose.dev.yml`:
  конфигурации валидны с одноразовыми тестовыми значениями обязательных переменных.
  Без секретов Compose корректно отказывается формировать конфигурацию.
- `git diff --check`: ошибок whitespace нет.

**Not verified:** применение миграций и соответствие схемы в живой PostgreSQL,
Docker build/run и CVE-скан образов, реальные nginx-заголовки, GitHub workflows после
пуша, восстановление копий, реальные AI-вызовы. Docker daemon отвечает отказом
доступа к сокету; привилегии и состояние внешней инфраструктуры не менялись.
