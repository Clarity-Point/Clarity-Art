# Творческие практики и личный альбом

## Сценарии

«Творческая пауза» открывается с главной и из меню. Каталог содержит пять
коротких карточек с временем, материалами, инструкцией и одним вопросом.
Участник может рисовать на бумаге или на холсте, скачать рисунок, завершить
упражнение в любой момент и отдельно сохранить работу или заметку в альбом.
Публичная страница карточек печатает выбранную карточку или весь набор на A4.
Серия из трёх карточек использует тот же каталог. Отметки сохраняются между
входами. Любой шаг можно повторить с сохранением уже пройденных шагов.

В личном альбоме рисунок и исходная подпись сохраняются вместе. Можно вернуться
к работе, добавить новую датированную подпись рядом с первой, скачать рисунок
или удалить работу. Участник составляет подборку к встрече из отмеченных
работ, отдельно выбирая рисунок и тексты, и видит предварительный просмотр.
После подтверждения выбранный аккаунт с ролью THERAPIST видит подборку в
кабинете. Владелец может отозвать её целиком. Получатель получает доступ только
к этой подборке. Доступ к дневнику и разрешения кабинета настраиваются отдельно.

## Границы данных

Существующие холст, сессия и маршрутизация переиспользуются. Личный альбом
имеет свои таблицы. Заметки практик идут в альбом и не проходят через дневник,
сервисы AI, аналитику состояния или галерею. Отдельный каталог выдаёт backend,
чтобы экран, печать и валидация сохраняемого прогресса использовали одни ID.

Работа хранит заголовок до 100 символов, необязательную исходную подпись до
600 символов и необязательный PNG, JPEG или WebP до 1 МиБ. Снимок бумаги
интерфейс уменьшает и перепаковывает в JPEG без исходных метаданных. Допускается
максимум 30 работ на аккаунт и 20 дополнительных подписей до 600 символов на
работу. В подборку можно включить до 8 работ, максимум 20 активных подборок
на владельца. Входящие подборки загружаются страницами до 20. Бинарный файл
хранится в PostgreSQL вместе с работой.
Это ограничивает объём, позволяет включить данные в существующий JSON-экспорт
и делает удаление работы и связанных разрешений атомарным. Вариант с общим
файловым томом потребовал бы отдельной очереди и восстановления дописей.
Списки и просмотр подборки загружают метаданные. Байты выдаёт отдельный
аутентифицированный маршрут с общей политикой API `no-store`.

Подборка хранит ID владельца и специалиста, порядок работ, снимок заголовка
и только выбранных подписей. Флаг включения изображения определяет доступ к
неизменяемому изображению этой работы. Новые подписи остаются приватными,
пока владелец не отправит следующую подборку. Внешние ключи привязывают
работу и подборку к одному владельцу. Удаление работы удаляет её из всех
подборок. Отзыв удаляет все снимки и блокирует чтение файлов. Строка с ID
отозванной подборки остаётся до удаления аккаунта, чтобы повтор старого запроса
не возобновил доступ. Удаление любого из аккаунтов отзывает соответствующий доступ
каскадно, удаление владельца также удаляет работы и прогресс. Список, открытие
подборки и запрос файла проверяют точного получателя с актуальной ролью
THERAPIST. Список содержит только имя автора, дату и количество работ.
При открытии подборки и возврате фокуса интерфейс запрашивает её содержимое.
Общее
согласие на просмотр дневника не требуется.

Права на чтение и изменение проверяются запросом к БД. Vue передаёт ожидаемый
ID сессии в `X-Expected-User-Id`, чтобы старая вкладка не записала личные данные
под сменившейся cookie. Квоты при записи сериализуются блокировкой
`FOR NO KEY UPDATE` строки владельца в транзакции Read Committed. Для работы и
подборки сервер выдаёт UUID ресурса, а ключ POST хранится в пределах владельца.
Повтор с тем же ключом возвращает прежний результат или HTTP 410 после удаления
работы либо отзыва подборки. Отметка удаления работы содержит только ключ
запроса и ID владельца.
События выдачи и отзыва содержат идентификаторы без текста и рисунков.
Экспорт владельца содержит прогресс, работы и подписи, изображения в base64 с
MIME и активные исходящие подборки. Входящие подборки остаются данными автора.

## Контракты и проверка

- `GET /api/practices/catalog` возвращает карточки и серии для упражнения и печати.
- `GET /api/practices/progress` и `PUT /api/practices/progress/:id` читают и
  отмечают выполненные практики текущего аккаунта. Повторная отметка идемпотентна.
- `GET/POST /api/practices/works`, `DELETE /api/practices/works/:id`,
  `POST /api/practices/works/:id/reflections` и `GET /api/practices/works/:id/image`
  работают только для владельца.
- `GET/POST /api/practices/shares` и `DELETE /api/practices/shares/:id`
  обслуживают владельца. Выбранный специалист использует
  `GET /api/therapist/practice-shares` для списка, `GET /api/therapist/practice-shares/:id`
  для содержимого и отдельный маршрут для изображения.
- Интеграционный сценарий в PostgreSQL проверяет изоляцию работ, выборочность
  подписей и рисунков, текстовую заметку, отзыв доступа и защиту от его отмены
  повторным запросом, удаление, параллельную запись на границе квоты и JSON-экспорт.
  Браузерный сценарий проверяет выбор упражнения, завершение серии, печатный
  маршрут, возврат к работе и предпросмотр доступа. Общая проверка использует
  `npm run check` и `npm run test:browser`.

Миграция добавляет таблицы без преобразования прежних данных. Проверяем её на
изолированной PostgreSQL. Прежний образ приложения можно вернуть без удаления
новых таблиц. Доступ к новым функциям появится после обновления кода и схемы.
