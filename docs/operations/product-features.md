# Уроки, черновики, история, восстановление доступа и модерация

## Обновление существующей установки

Перед обновлением создайте резервную копию PostgreSQL по [инструкции](runbook.md).
Новая схема применяется обычной командой из каталога `backend`:

```sh
npx prisma migrate deploy
npx prisma generate
```

Миграция `20261016090000_complete_product_features` добавляет таблицы черновиков,
ссылок восстановления, жалоб, скрытых работ и ручных отметок настроения. Старые
пользовательские записи сохраняются. Материалы трёх вводных уроков заполняются
только у известных демонстрационных курсов и только если материал пустой.
Демо-seed в production запускать не нужно.

Миграция `20261110180000_preserve_user_data` добавляет версии записей дневника,
очередь удаления файлов и индексы истории. Она также запрещает каскадное удаление
пользовательского прогресса и сданных заданий при удалении курса администратором.
Обновляйте backend и frontend вместе после миграции; старую открытую вкладку
нужно перезагрузить перед редактированием дневника.

## Восстановление пароля

Задайте на сервере `SMTP_URL`, `MAIL_FROM` и правильный `FRONTEND_URL` с публичным
HTTPS-адресом приложения. Примеры переменных есть в обоих `.env.example`; Compose
передаёт их backend. Для SMTP используйте TLS или STARTTLS согласно настройкам
провайдера. Секреты SMTP не должны попадать во frontend или Git.

На `/forgot-password` пользователь вводит адрес. Ответ одинаков для существующих
и отсутствующих аккаунтов; доставка выполняется после ответа. Поэтому успешный
экран подтверждает приём запроса, а не доставку письма. Ошибки доставки доступны
в серверном журнале без адреса получателя или кода. Без SMTP доставка отключена.

Ссылка действует 30 минут, хранится в базе в виде SHA-256 хеша и принимается один
раз. Новый запрос возможен раз в минуту для одного аккаунта. Оба endpoint имеют
ограничение 10 запросов за 15 минут с одного IP. Код передаётся во фрагменте URL,
удаляется из адресной строки экраном восстановления и отправляется серверу только
в теле POST. Успешный сброс отзывает все сессии; вход с новым паролем выполняется
отдельно. После обычной смены пароля старые ссылки перестают действовать.

Для проверки доставки используйте тестовый SMTP-сервер и отдельный тестовый
аккаунт; не отправляйте диагностические письма реальным пользователям.

## Пользовательские функции

- **Редактирование дневника:** опубликованные записи имеют собственную `version`.
  PUT передаёт версию, полученную при открытии редактора; конфликт возвращает 409,
  введённый текст остаётся доступен для копирования. Запрос без версии получает 400.
- **Уведомления:** первая страница содержит до 50 записей; «Загрузить ещё» открывает
  следующие. Счётчик показывает все непрочитанные уведомления, включая незагруженные.
  API сохраняет ответ-массив, принимает `cursor`/`limit` (1–100), возвращает
  `X-Next-Cursor` и `X-Unread-Count`. При смене аккаунта старые ответы отбрасываются.
- **Уроки:** материал открывается внутри курса, доступны предыдущий и следующий
  урок. Последний выбранный урок хранится на сервере. Чтение само по себе не
  увеличивает прогресс: участник отдельно отмечает прохождение. Материал и
  название редактируются в админ-панели; поддерживается Markdown без raw HTML.
- **Черновики:** один черновик дневника и отдельный для каждого задания; автосохранение
  через 700 мс после ввода, без хранения текста в localStorage. Версии предотвращают
  перезапись изменений другой вкладки. При конфликте сначала скопируйте свой текст,
  затем загрузите серверную версию. При ошибке серверной загрузки ввод заблокирован
  до повторной загрузки, чтобы не затереть существующий черновик. Перед переходом
  приложение пытается сохранить текст; при неудаче предупреждает о потере изменений.
- **История:** `/history` ищет по всему дневнику, анализам рисунков, беседам и домашним
  заданиям текущего аккаунта. Фильтры даты включают последний выбранный день в
  локальном часовом поясе. Пагинация выполняется сервером; беседы и записи дневника
  открываются по прямой ссылке, даже если отсутствуют в последних записях профиля.
- **Настроение:** в дневнике и аналитике доступна личная отметка от 1 до 5 с
  необязательной заметкой. Одна отметка на локальный календарный день, повторное
  сохранение обновляет её. История загружается порциями по 30, график показывает
  последние 30 загруженных отметок. Это самооценка пользователя; она не поступает
  в ИИ и не смешивается с автоматически определёнными рисками. Можно удалить
  отдельную отметку. Черновики и отметки входят в JSON-экспорт аккаунта и удаляются
  каскадно при удалении аккаунта.

## Модерация галереи

Участник может скрыть работу для себя или отправить жалобу с причиной и пояснением.
Жалоба также скрывает работу для заявителя; повторная жалоба на ту же работу не
создаёт дубликат. Фильтр «Показать скрытые мной работы» позволяет вернуть работу.

Раздел `/admin/moderation` доступен только роли ADMIN, включая API. Очередь показывает
жалобы по статусам и позволяет заблокировать работу, отклонить жалобу или восстановить
заблокированную работу. Блокировка закрывает доступ к изображению другим участникам,
скрывает публикацию из галереи и запрещает её повторную публикацию владельцем.
Владелец сохраняет доступ к своей работе; администратор получает доступ к изображению
из жалобы для рассмотрения. Операции модератора попадают в аудит без текста жалоб.

## Проверка перед выпуском

`npm run check` проверяет стиль, типы, модульные тесты, сборки и зависимости.
`npm run test:browser` проверяет интерфейсы и пользовательские сценарии.
Для интеграционных проверок нужен отдельный PostgreSQL с уже применёнными миграциями:

```sh
RUN_DATABASE_TESTS=true DATABASE_URL='postgresql://user:password@localhost:5432/clarity_test' npm test -w backend
```

Проверки создают случайные тестовые аккаунты и курс, а затем удаляют только свои
данные. Проверяются конкурирующие сохранения, изоляция аккаунтов, поиск и пагинация,
позиция урока, модерация, сброс пароля и доставка письма в локальный SMTP-сервер.
В CI этот режим включён для временной PostgreSQL 16. На реальную рабочую базу
интеграционные проверки направлять не следует.

## Повторная сдача и проверка заданий

Повторная отправка сбрасывает прежнюю оценку и отзыв. При проверке администратор
отправляет `submissionDate` просмотренной версии вместе с `userId`, `homeworkId`,
`grade` и `analysisText`. Если участник уже отправил новую версию, API возвращает
409; нужно перечитать работу. Старые API-клиенты без `submissionDate` получают 400.

Новые пароли проходят общую проверку размера UTF-8 перед bcrypt, чтобы пароль не
обрезался молча. Вход с существующими паролями сохраняет совместимость.

## Архив курсов и управление организацией

Миграция `20261111010000_content_management` добавляет `Course.archivedAt`,
`ImageAnalysis.moderationVersion` и индекс списка сдач. Примените её перед обновлением
backend; frontend обновите вместе с backend. Миграция не удаляет пользовательские данные.

В админ-панели у курса есть «В архив» и «Вернуть в каталог». Архив скрывает курс из
общего каталога, сохраняя прямые ссылки, чтение материалов, сдачу заданий и прогресс.
Это управление видимостью в каталоге, а не запрет доступа или приватный режим.
`GET /api/admin/courses` возвращает все курсы администратору, публичный `/api/courses`
возвращает только активные. `PUT /api/admin/courses/:id/archive` принимает
`{ "archived": true }` или `false`. Событие `admin.course_archived` содержит ID и статус.

На странице организации администратор может передать управление обычному участнику
той же организации. Требуются email участника, текущий пароль и подтверждение.
`POST /api/org/transfer-admin` принимает `email` и `password`; обе роли и уведомление
новому администратору меняются в одной транзакции. При изменении состава или прав
между проверками возвращается 409. Чужой участник, другой администратор или терапевт
не может стать преемником через эту операцию. Глобальная роль ADMIN не передаётся.
Прежний администратор остаётся участником; он может отдельно выйти в профиле.
Событие `org.admin_transferred` содержит ID участников и организации, без email/пароля.

## Пагинация рабочих списков

Администратор ищет сдачи по email или названию задания и выбирает «Все работы»,
«Ожидают проверки» или «Проверены». Терапевт ищет по имени/email среди закреплённых
за ним участников с действующим согласием. «Загрузить ещё» сохраняет применённые
условия; изменение текста поиска до нажатия «Найти» не меняет следующие страницы.

Оба endpoint сохраняют ответ-массив и принимают `limit` (1–100, по умолчанию 50),
`cursor` и `q` (до 120 символов). `/api/admin/submissions` также принимает
`status=all|pending|graded`. `X-Next-Cursor` отсутствует на последней странице.
`X-Total-Count` и `X-Pending-Count` для сдач относятся ко всему списку, независимо
от фильтра. `X-Total-Count` и `X-Attention-Count` терапевта относятся к текущему поиску.
Заголовки доступны frontend через CORS. Списки живые: изменение приоритета или даты
сдачи между страницами может изменить порядок; для актуального среза повторите поиск.

## Конфликты модерации и несохранённый дневник

Очередь жалоб теперь возвращает `image.moderationVersion`. Решение по жалобе и
восстановление публикации передают это значение как `version` в JSON. Любое решение
увеличивает версию публикации. Старая версия получает 409, запрос без версии — 400.
Перед повторной попыткой нужно обновить список. Это защищает и разные жалобы на одну
публикацию: старая кнопка восстановления не отменит новую блокировку.

Редактор опубликованной записи дневника предупреждает перед переходом, отменой
редактирования или выбором другой записи с несохранённым текстом. При закрытии вкладки
используется стандартное предупреждение браузера; его показ зависит от браузера.
Текст редактирования не записывается в localStorage. При смене аккаунта он очищается.
Автосохранение новых записей в серверный черновик работает как прежде.
