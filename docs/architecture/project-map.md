# Карта проекта

Проект — npm workspaces с единым `package-lock.json`. Устанавливайте зависимости
из корня через `npm ci`. Не создавайте отдельные lock-файлы в приложениях.

```text
Clarity-Art/
├── backend/
│   ├── prisma/             схема, миграции, начальное наполнение
│   ├── src/
│   │   ├── config/         конфигурация, Prisma, журналы, AI
│   │   ├── controllers/    обработчики HTTP-запросов
│   │   ├── middleware/     сессии, роли, лимиты, происхождение запросов, ошибки
│   │   ├── schemas/        проверка структуры входных данных
│   │   ├── security/       проверка текста и изображений
│   │   ├── services/       прикладная логика, хранение изображений, приватность
│   │   └── tests/          тесты API и бизнес-правил
│   └── Dockerfile          производственный образ API
├── frontend/
│   ├── public/             PWA-иконки и звуковые дорожки
│   ├── src/
│   │   ├── assets/         тема; изображения в assets/images/
│   │   ├── components/     переиспользуемые элементы интерфейса
│   │   ├── composables/    логика экранов и поведения
│   │   ├── router/         маршруты и проверки доступа для навигации
│   │   ├── stores/         состояние Pinia
│   │   └── views/          страницы маршрутов
│   ├── nginx.conf.template проксирование, SPA и кеширование
│   └── security-headers.conf общие защитные HTTP-заголовки
├── tests/browser/          проверки адаптивности, доступности и поведения
├── scripts/                инструменты проекта, включая аудит зависимостей
├── docs/
│   ├── architecture/       устройство проекта
│   ├── operations/         эксплуатация
│   ├── audits/             результаты проверок и ограничения
│   └── outreach/           партнёрства и безопасный пилот
├── .github/                CI, публикация образов, Dependabot, шаблоны
└── docker-compose*.yml     окружения разработки и эксплуатации
```

Запрос проходит `браузер → nginx /api → middleware Express → controller → service → Prisma/PostgreSQL`.
В разработке nginx заменяет прокси Vite. UI-проверка роли помогает навигации;
реальную границу доступа обеспечивают middleware и фильтры запросов backend.

Сессионная cookie — HttpOnly; пользовательские дневники, чаты и профиль держатся
в оперативной памяти клиента. PWA кеширует только статические ресурсы сборки.
Рисунки хранятся в отдельном томе и выдаются через авторизованный API.
Внешний AI включается конфигурацией оператора и требует согласия пользователя.

Новые страницы размещайте в `views`, общие элементы — в `components`, состояние —
в `stores`, повторяемое поведение — в `composables`. Не переносите API-контракты
в визуальные компоненты. Для изменения базы добавляйте миграцию, не редактируйте
уже применённые миграции.
