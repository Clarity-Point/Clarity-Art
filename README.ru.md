## Что это

Full-stack веб-приложение, где человек ведёт дневник, использует опционального
поддерживающего ИИ-собеседника, загружает или рисует изображение для
**рефлексивных** подсказок, проходит курсы с домашними заданиями и следит за
активностью через стрики, челленджи и таблицу лидеров. Есть ролевые кабинеты для
**терапевтов** (только при явном предоставлении доступа пользователем), админов
организации (privacy-protected групповые агрегаты) и админов платформы (управление
курсами).

Все ИИ-функции **опциональны и провайдер-агностичны** (см. ниже). Аналитические
«инсайты» — прозрачные эвристики на правилах, а не клинические оценки.

## Возможности

- **Дневник** — записи с календарём активности и опциональными неклиническими подсказками.
- **ИИ-чат** — опциональный поддерживающий собеседник со стримингом и историей сессий.
- **Рефлексия творчества** — загрузка или рисование на холсте для опциональных рефлексивных подсказок; не арт-диагностика.
- **Курсы** — программы арт-практик с модулями, уроками и домашними заданиями.
- **Практики** — дыхательные упражнения и плеер успокаивающего аудио (встроенные).
- **Прогресс** — активность, достижения, челленджи, лидерборд, галерея.
- **Safety notice** — консервативная проверка ключевых слов может показать ресурсы поддержки; это не crisis detection, triage или emergency care.

## Быстрый старт — Docker (без клонирования, без сборки)

На каждый релиз публикуются готовые multi-arch образы (amd64 · arm64), поэтому
для запуска всего стека нужны два файла и одна команда:

```bash
curl -O https://raw.githubusercontent.com/Clarity-Point/Clarity-Art/main/docker-compose.yml
curl -o .env https://raw.githubusercontent.com/Clarity-Point/Clarity-Art/main/.env.example

# Задайте два обязательных значения
sed -i "s/^JWT_SECRET=.*/JWT_SECRET=$(openssl rand -hex 32)/" .env
sed -i "s/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=$(openssl rand -hex 16)/" .env

docker compose up -d
```

Приложение доступно на **http://localhost**. Миграции применяются автоматически при старте.

| Образ                                        | Назначение                     |
| -------------------------------------------- | ------------------------------ |
| `ghcr.io/clarity-point/clarity-art-backend`  | API (Express · Prisma)         |
| `ghcr.io/clarity-point/clarity-art-frontend` | SPA + nginx, проксирует `/api` |

Можно закрепить релиз вместо отслеживания `latest`, задав `BACKEND_IMAGE` и
`FRONTEND_IMAGE` в `.env`. Полезные команды:

```bash
docker compose logs -f          # смотреть логи
docker compose pull && docker compose up -d   # обновление
docker compose down             # остановить (добавьте -v, чтобы также удалить базу данных)
```

## ИИ: опционально, локально, без привязки к вендору

ИИ-функции (чат, рефлексия творчества/профиля и опциональный текстовый safety signal) работают по
**OpenAI-совместимому протоколу `/chat/completions`**, поэтому подходит любой
такой сервер — в том числе полностью локальный. Укажите его в `backend/.env`:

```bash
AI_BASE_URL=http://localhost:11434/v1   # напр. Ollama / LM Studio / vLLM / LocalAI
AI_MODEL=llama3.1
AI_VISION_MODEL=llava                    # для анализа рисунков
# AI_API_KEY — оставьте пустым для локальных серверов без ключа
```

Если ИИ-провайдер **не** настроен, приложение всё равно работает от начала до
конца: ИИ-функции деградируют до заготовленных спокойных ответов. Обязательной
облачной зависимости нет, данные не обязаны покидать вашу машину.

## Логирование

Структурированное логирование через [pino](https://getpino.io), полностью настраивается
через переменные окружения — один и тот же образ работает в любом режиме без пересборки.

| Переменная   | Значения                                                              | По умолчанию                                    |
| ------------ | --------------------------------------------------------------------- | ----------------------------------------------- |
| `LOG_LEVEL`  | `trace` `debug` `info` `warn` `error` `fatal` `silent`                | `debug` (dev) · `info` (prod) · `silent` (test) |
| `LOG_FORMAT` | `pretty` (с подсветкой, для человека) · `json` (по объекту на строку) | `pretty` (dev) · `json` (prod)                  |

```jsonc
// LOG_FORMAT=json — готово для Loki, Datadog, CloudWatch или ELK
{
  "level": "info",
  "time": 1730000000000,
  "service": "clarity-backend",
  "requestId": "a1b2…",
  "method": "GET",
  "path": "/api/courses",
  "status": 200,
  "durationMs": 12.4,
  "msg": "GET /api/courses 200",
}
```

- У каждого запроса есть заголовок **`X-Request-Id`**; тот же id появляется в
  строке лога и в ответах об ошибках, так что по одному id можно найти точную
  запись на сервере.
- Уровень записи зависит от кода статуса: `5xx` → error, `4xx` → warn, иначе info.
- **Учётные данные и заголовки авторизации централизованно маскируются**, а тела
  запросов никогда не логируются — они регулярно содержат текст дневника и
  сообщения чата.
- Логи контейнера ротируются по 10 МБ × 3 файла, поэтому долго работающий хост
  не переполнится.

## Health checks

| Эндпоинт        | Значение                                                                   |
| --------------- | -------------------------------------------------------------------------- |
| `/health`       | Liveness — не зависит от внешних сервисов, работает даже при упавшей БД.   |
| `/health/ready` | Readiness — `503`, пока база данных не отвечает. Используйте для роутинга. |

Оба образа поставляются с Docker `HEALTHCHECK`, а бэкенд корректно завершает
работу по `SIGTERM` (сначала дренирует соединения, отключает Prisma, затем
выходит).

Для публичного
HTTPS-развёртывания также задайте `COOKIE_SECURE=true`, завершайте TLS на обратном
прокси и не открывайте PostgreSQL наружу.
